20组配置。valid CLI返回0且status=not_run；invalid/stale输入返回2和
结构化field/code诊断，stdout无成功结果。参考/严格示例均是合同输出，
backend_implemented=false、protocol_validated=false，样本数0、指标null。
Node仅为HTML oracle审计依赖；运行CLI无需Node、gem5、GPU或网络。

仓库pre-commit/commit-msg hooks已安装，阶段提交保持启用；完整hook
结果以实际提交检查为准，不绕过失败。原HTML、Base Spec和项目根许可证
未修改。测试代码采用用户指定cary署名，继承根COPYING/LICENSE。

## 范围和剩余项

- `0=auto`值保留并列为unresolved，M1负责计算建议；显式容量不放大。
- M0只作声明/结构检查。物理port/lane布线、地址路由和完整RX/core/
  staging/replay backing均显式unvalidated，不能将配置通过当作可部署证明。
- 透明拓扑子集为单根、root/endpoint叶节点，root→endpoint路径使用统一
  `switches`数；不是全图Switch总数，允许同路径深度的多分支。
- Shared FC TX字段是所选FLIT profile的能力声明，不是已实现Shared FC
  gate；RX启用可选，详细协议执行在M2/M3。
- RCB角色是接收Read Completions的System Element；该检查不证明实际
  Completion分段/重组正确。参考模式保留页面RCB/Tag预算近似。
- 支持字段、类型和能力合同不等于完整PCIe6规范覆盖；ECN/errata仍需在
  相应功能冻结时核对。补充databook当前缺失，不阻塞M0。
- M0不改gem5构建注册，也未编译或运行仿真；下一阶段为M1参考sizing、
  JSON adapter与事件语义实现，已有M0数据/测试可作为其输入基础。
